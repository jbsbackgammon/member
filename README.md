# 選手素材管理 (`member`)

JBS向けの選手素材管理・写真出力・名札出力ツールです。

## 会員データ

会員の追加・削除は、GitHub の `images/` フォルダへ顔写真を追加・削除することで行います。
ツール画面上では会員の追加・削除・顔写真登録は行いません。

顔写真は **1人1枚** とし、ファイル名を次の形式にします。

```text
名前_名前英語.png
```

例:

```text
images/柳 暢祐_YANAGI Nobusuke.png
```

ファイル名は変更せず、そのまま GitHub に保存します。
そのため GitHub から画像をダウンロードした場合も `柳 暢祐_YANAGI Nobusuke.png` の名前を維持できます。

GitHub Pages のデプロイ時に `scripts/build-members.py` が `images/` を読み取り、ファイル名の最初の `_` を区切りとして以下を自動判定します。

- `_` より前 → 名前
- `_` より後 → 名前英語

生成された `data/members.json` を画面が読み込みます。`data/members.json` は自動生成ファイルのため、リポジトリへ手動で保存する必要はありません。

## 写真の自動退避

`images/` 直下にある同名画像を異なる内容の画像で上書きすると、GitHub Actions が更新前の画像を `images/old/` に保存します。ファイル名は元の名前に更新日時（日本時間、年月日・時分秒）と更新コミットIDを付けた形式です。

- 新規追加・同一内容の再登録・削除では退避しません。
- 複数の上書きを検出し、過去の画像を個別に保管します。再実行しても同じ退避ファイルは重複しません。
- 導入後の main の変更を対象とします。通常の上書き運用を継続してください。
- `images/old/` は選手一覧・公開用Pages成果物の対象外です。ただし、GitHubリポジトリ自体が公開されている場合は履歴画像も閲覧可能です。
- 退避コミットには GitHub Actions のトークンを使用し、その実行内で引き続き本番デプロイします。リポジトリの設定で Actions に書き込み権限が必要です。

## 名札

会員リストで対象者にチェックを入れ、「名札出力」から印刷します。
A4縦・2列×5段の1ページ10枚です。名札は91mm×55mm、用紙の上下左右中央に配置します（左右各14mm、上下各11mm）。10名を超えた場合は自動で次ページを作成します。
印刷倍率は100%（実際のサイズ）、余白なしを推奨します。PDFとして保存する場合の既定ファイル名は「名札.pdf」です（ブラウザ・OSによって異なる場合があります）。

名札文言は画面上で出力時に変更できます。帯色は「色なし」を含む9種類から選択できます。

## 設定保存・設定呼出

- 「設定保存」：選手の選択状態・名札文言・名札帯色を、現在のブラウザのローカルストレージに保存します。保存成功時はボタンに2秒間「保存完了」と表示します。
- 「設定呼出」：保存日時と選択人数の一覧（新しい順、最大100件・ブラウザの保存容量に依存）から選び、設定を復元します。
- 保存は端末・ブラウザごとです。別の端末で使用する場合やバックアップには従来の「JSON出力」「JSON取込」を使用してください。
- 選手素材（写真ファイル）自体は保存しません。

## 共通UI

操作画面は [common/ui.css](https://jbsbackgammon.github.io/common/ui.css) を直接参照します。
色、フォント、ボタン、入力欄、チェックボックス、ダイアログ、余白などの共通定義を利用します。選手一覧の表は common と同じ `jbsui-reference-table` を直接適用し、列幅・配置や名札の帯色、印刷寸法は member 固有の定義として `style.css` に残しています。

## GitHub Pages

リポジトリ名: `member`

GitHub Pages の Source は **GitHub Actions** を使用します。
`main` への push で会員一覧を自動生成し、そのまま公開します。
